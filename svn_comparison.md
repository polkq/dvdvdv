# Git vs SVN — ответы

## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?

В Git ветка — это указатель на коммит (легковесная ссылка). Создание ветки почти мгновенное и почти не занимает места.

В SVN ветка — это копия директории в репозитории (`svn copy`). Операция тяжелее, дольше и сильнее нагружает центральный сервер, поэтому ветвление считают «дорогим».

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

Нет. SVN — централизованная система: настоящий коммит всегда идёт на сервер. Без сети можно только править файлы локально, но зафиксировать ревизию в истории репозитория нельзя.

В Git полный репозиторий есть локально, поэтому `git commit` работает офлайн; в сеть уходит уже `git push`.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

- **Legacy-проекты** в банках, госсекторе и крупных компаниях, где уже выстроены процессы и права вокруг SVN.
- Когда нужна **строгая централизация**: один сервер как единственный источник правды, простой контроль доступа к путям.
- Команды, которым важна **простая модель** «один trunk / одна центральная история» без распределённых веток и сложного merge/rebase.
